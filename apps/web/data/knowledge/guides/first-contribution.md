## How to start contributing to open source

1. **Pick one project you can actually use.** Approachable beats famous: a smaller, well-documented project teaches you more, faster. Browse organizations on the [Programs](/programs) page, the [CNCF Landscape](https://landscape.cncf.io) or [CLOTributor](https://clotributor.dev).
2. **Use it first.** Install it, follow its tutorial, read the docs.
3. **Read** its README, CONTRIBUTING file, code of conduct and how it reviews PRs.
4. **Join its community chat** (Slack, Discord, Matrix). Ask OpenSourceX for "<org> slack link". Introduce yourself in the contributors channel.
5. **Find a starter task:** issues labelled `good first issue` or `help wanted`, a docs fix, a failing test, or a bug you found yourself.
6. **Comment on the issue** to say you are working on it (or ask to be assigned), then set up the project locally.
7. **Open a small, focused pull request** and see it all the way through review before you take on more.
8. **Respond to feedback quickly** and politely, and update the PR.

## Contributions that are not code

Solid bug reports, reproducing issues, reviewing other people's PRs, improving docs, answering questions in the chat, triaging issues, joining community meetings, and writing blog posts all count. Mentors value people who take part in the project's life, not only PR counts.

## Finding good first issues on GitHub

- On any repository: **Issues → Labels → good first issue**.
- GitHub search: `is:issue is:open label:"good first issue" language:go`, or another language.
- [CLOTributor](https://clotributor.dev) for CNCF projects, and [goodfirstissue.dev](https://goodfirstissue.dev) for popular projects.
- If an issue already has an assignee or an open PR, pick another one or ask before starting.
